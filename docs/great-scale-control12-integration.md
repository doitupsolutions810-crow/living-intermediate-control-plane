# Great-Scale × AVRONE CONTROL12 integration

## Source reviewed

Repository: https://github.com/doitupsolutions810-crow/great-scale  
Default branch: `main`  
README geometry version: `0.3.0`

The source describes "three embeddings of one state" and lists Watch / Observer / Forward / Adjacent / Down. It states these laws:

- Keep the mean (zero-mode ≈ φ).
- Residual partition 4+3+1.
- Ψ never below cone √5−2.
- Only add geometry generated by the scale.

Its Geometry v0.3.0 description names a gold–gray spindle, residual cone, height H=S, radial λ=φ^(−n), ninefold symmetry, inward fold 0.8, and sequence lattice.

## Integration choice

CONTROL12 receives a pure, deterministic adapter at `platform/src/scale/great-scale.mjs`. It converts the source's explicit laws into named conformance checks suitable for orchestration, verification, and evidence reports. It does not replace CONTROL12's five orchestration roles, trust network, attestation, or execution policy.

The adapter is intentionally a **conformance checker**, not a claim that Great-Scale is empirically validated or that these values are universal physical laws. The source uses "≈ φ" but does not specify a tolerance; the adapter uses an explicit default tolerance of 0.05, caller-overridable from 0 to 1. This is an implementation default, not a source-derived constant.

The source's phrase "three embeddings" conflicts numerically with its five listed labels. The adapter preserves all five labels as optional coverage metadata rather than resolving that ambiguity.

## API

Import `validateGreatScaleState(input)` and pass a state containing:
- `zeroMode`
- `residualPartition`
- `psi`
- `geometry.heightRatio`, `radialLambda`, `n`, `symmetry`, `inwardFold`, `generatedByScale`
- optional `perspectives` and `tolerance`

Decisions:
- `READY`: every check was provided and passed.
- `INCOMPLETE`: no check failed, but at least one required input was not provided.
- `NOT_READY`: one or more checks failed.
- `INVALID_INPUT`: invalid tolerance.

The result carries per-check status, failed/missing gates, source repository/version, and a disclaimer. Null, primitive, and array inputs return `INVALID_INPUT` rather than throwing.

### CONTROL12 cockpit action

The adapter is exposed as `POST /api/v1/cockpit/action` with `{ "action": "great_scale_validate", "state": { ... } }`. The action also accepts the state fields alongside `action` in the same request body. The route passes through the server's shared POST authentication guard; do not expose it through an unauthenticated proxy. It only evaluates input and does not trigger agent execution or alter budget state.

## Safe rollout

1. Run this validator as a non-authoritative review gate / evidence annotation.
2. Keep execution, authentication, authorization, budget accounting, and attestation decisions under their existing CONTROL12 controls.
3. Do not use a `READY` result as a security attestation or production deployment approval.
4. Keep the cockpit action behind CONTROL12's shared POST authentication guard; verify proxy/auth configuration in deployment before exposing it.
